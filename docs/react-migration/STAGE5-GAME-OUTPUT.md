## Comportamiento implementado

LaunchService sustituye la decodificación asíncrona independiente de fragmentos y el array creciente errPromises por un Writable con backpressure en cada pipe. iconv-lite, ya instalado, mantiene un decoder incremental por canal. Se conserva ASCII anterior al primer carácter no ASCII, se prefiere UTF-8 válido y se consulta el detector existente para texto legacy; se manejan BOM y secuencias partidas. stdout y stderr conservan su propio orden y codificación. La secuencia nueva indica el orden de publicación Native entre ambos canales; no inventa un orden total de escritura del sistema operativo entre dos pipes distintos.

Los eventos conservan pid/stdout/stderr y añaden launchId, gameDirectory, side y sequence. Se actualizan LaunchServiceEventMap y Monitor; los consumidores Vue que solo leen los campos anteriores siguen siendo compatibles. Los identificadores generados se colocan después de las opciones recibidas, para que opciones adicionales no suplanten PID/launchId. La ambigüedad de logs compartidos solo se marca para el mismo lado.

Las emisiones tienen un máximo de 65.536 unidades UTF-16 sin cortar pares sustitutos. Cada resumen retenido de stderr, stdout previo a ready y salida combinada tiene un máximo de 1.048.576 unidades UTF-16, con marcador de truncamiento. Son límites de texto, no una medición de bytes o heap total. No se truncan los archivos guardados por el juego. El buffer inicial de detección está acotado y la prueba de backpressure verifica que el productor deja de generar mientras el detector está bloqueado.

Los listeners se instalan antes de esperar la escritura del historial. El watcher del core recibe stdout ya decodificado, conserva fragmentos de líneas, detecta marcadores partidos y espera el final de stdout antes de publicar sus datos de salida. Su fallback de crash y cola de línea tienen límite de 65.536 unidades UTF-16. Native espera además stderr e historial antes del evento final, para incluir el último texto. Retira el proceso del registro al exit real, conserva su hora para duración/captura y comprueba identidad del objeto antes de retirar un PID reutilizado. Se ignoran ready tardíos y salidas repetidas. Las pruebas cubren salida rápida durante historial lento, texto posterior a exit, PID reutilizado y duración independiente del retraso de I/O.
