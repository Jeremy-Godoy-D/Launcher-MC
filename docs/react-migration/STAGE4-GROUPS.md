# Etapa 4 parcial — gestión de grupos existentes

2026-10-26, America/Bogota. Código identificado en STAGE4-GROUPS.json. Biblioteca permite renombrar o disolver grupos desde su encabezado, incluso cuando no hay instancias Java visibles. No se cierran K02/K03/K04 ni las tres gates de etapa 4.

El diálogo captura una revisión de los grupos y usa el método nativo existente `updateInstanceGroups`, con comparación de la revisión completa y guardado atómico en cola. Un cambio desde otra ventana se rechaza, conserva lo escrito y ofrece volver a revisar. Los nombres vacíos, mayores de 100 caracteres o duplicados sin distinguir mayúsculas se rechazan en el formulario/modelo. El contrato nativo legacy no se estrecha ni se añaden endpoints IPC para esta interfaz.

Renombrar conserva identificador, color, miembros y posición. Disolver requiere marcar la opción y confirmar; transforma los miembros en entradas sin grupo en la misma posición. Conserva miembros desconocidos/de otras ediciones, otros grupos e instancias; no llama a borrar instancias ni archivos. Si desaparece el grupo usado como filtro, Biblioteca vuelve a todos los grupos. La selección de instancia permanece y el diálogo devuelve el foco al botón de gestión. Se pausa el ambiente mientras está abierto, como los demás diálogos.

La spec 21 verifica conflicto nativo real por otra edición concurrente, nombre duplicado, revisión nueva, renombrado persistido, recarga, filtrado y disolución. Comprueba el JSON de grupos en su formato de disco (rutas administradas relativas), las tres instancias, el miembro desconocido, el color, el orden, la selección y un mundo centinela. El segundo caso abre la gestión sin instancias, muestra el vacío y disuelve un grupo legacy vacío sin crear instancias. Capturas y Axe cubren claro/oscuro y 1200×720/800×400; no sustituyen una revisión manual completa AA.
