## Comportamiento y garantías

El borrador mantiene una base de los campos de ejecución. Cambios de nombre, descripción o tiempo jugado no reinician los campos editados. Los campos externos que no se tocaron se incorporan; los conflictos conservan el valor local y bloquean el guardado hasta leer explícitamente los valores actuales. La memoria se revisa como un grupo: modalidad, mínimo y máximo. Los argumentos siguen siendo arrays exactos del bloque anterior, con lista vacía propia distinta de herencia.

Java, los tres flags y RAM conservan sus valores opcionales. Los flags permiten heredar, activar o desactivar; restablecer envía null para quitar la preferencia, sin fijar false. RAM conserva herencia, auto, asignación manual y gestión por Java. Cada límite vacío hereda por separado; 0 conserva el contrato existente de no fijar ese límite a Java. No se cambia ese significado ni se convierte auto/false en manual al guardar otro campo. Editar ancho/puerto mantiene resolution.monitor y server.name. Los valores numéricos se mantienen como texto durante la edición para poder corregir un dato inválido.

InstanceService.editInstanceSettings valida una lista cerrada de campos, estructuras/rangos y presupuestos de argumentos; rechaza datos desconocidos y errores sin incluir los valores enviados. Solo acepta una instancia Java registrada. Serializa los cambios por instancia, compara los campos revisados antes y después de las esperas, comprueba procesos por identidad física de carpeta y guarda únicamente los cambios solicitados. Ante un fallo del escritor atómico revierte en memoria solo los valores propios que sigan coincidiendo con lo aplicado; conserva cambios distintos de otros consumidores y devuelve error. La UI mantiene el borrador capturado, sin anunciar éxito antes de terminar la escritura. Se conserva editInstance para sus consumidores actuales; su comprobación de obsolescencia también protege todo el grupo RAM, sin añadir locks que bloqueen a callers que ya los poseen.

La salida por rutas, historial, selección entre instancias y cierre Native ofrece Guardar y continuar, Descartar y continuar o Seguir editando. LibraryProvider conserva por ventana la instancia que tiene un borrador, incluso si otra ventana cambia la selección guardada. Una selección local confirmada vuelve a comprobar el destino antes de continuar. No se guardan los borradores en localStorage/sessionStorage. Se usa [useBlocker](https://reactrouter.com/api/hooks/useBlocker) y [beforeunload de Electron](https://www.electronjs.org/docs/latest/api/browser-window#event-close); un cierre forzado del proceso/SO queda fuera de esta garantía. Un intento de recarga con borrador se cancela mediante beforeunload; el diálogo ofrece continuar cerrando, no reanuda automáticamente esa recarga.

El selector Java reutiliza el diálogo Native y JavaService.resolveJava. Esperas/cancelación/error conservan el borrador; al terminar incorpora cambios externos de campos intactos. Las operaciones pendientes bloquean una salida que perdería el formulario. Los errores reciben foco y quedan visibles; la franja de acciones reserva espacio para los campos al desplazarse en la ventana mínima. Se mantienen tokens, Lucide, Radix y el paisaje/cristal aprobados, sin dependencias nuevas.
