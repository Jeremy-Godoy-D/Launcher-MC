## Comportamiento

`installDatapackFromMarket` valida primero una instancia Java registrada o el depósito propio, el mundo, la carpeta de datapacks y las sesiones activas. La petición conserva únicamente referencias de proveedor/nombre/icono permitidas; descarta `domain`, rutas y otros campos enviados por el renderer. Modrinth exige los IDs base62 de ocho caracteres que admite el cliente existente; las listas vacías se rechazan.

Las descargas se realizan en una carpeta temporal propia bajo la raíz nativa, fuera del mundo y de los mutex mantenidos durante escrituras. Cada resultado debe ser un archivo regular directamente dentro de esa carpeta. Antes de publicar se revisan todos los archivos, nombres y metadatos, se fija el hash SHA-256 y se vincula el destino a su identidad exacta. Durante la aplicación se comprueba de nuevo el mundo, la carpeta de datapacks y el origen. Se reutiliza el protocolo de revisión/aplicación con mutex, guardas de sesiones y publicación exclusiva; una primera importación puede crear la carpeta, sin invalidar injustificadamente el resto del lote.

Los sidecars CurseForge/Modrinth forman parte de la operación revisada y se publican exclusivamente. Un sidecar huérfano o competidor no se adopta ni reemplaza. Las copias instaladas son independientes del archivo temporal/caché. `installFromMarket` de mundos también usa staging y la importación revisada, conservando archivos del usuario que antes podían colisionar con la descarga del ZIP en el depósito.

El proveedor espera a que terminen todas las descargas de un lote antes de propagar el primer fallo: la limpieza no puede retirar el staging mientras otra descarga escribe en él. Una respuesta vacía se trata como error, sin informar instalación correcta. La limpieza se limita a la carpeta temporal creada por esta operación, con identidad y raíz verificadas; no sigue una carpeta sustituida por un enlace.

Un fallo durante la publicación de metadatos o de archivos posteriores puede conservar archivos anteriores completos. No se hace rollback destructivo de esos archivos ni de un destino competidor. La instalación crea `session.lock` cuando la guarda lo requiere; no cambia `level.dat`.

## Correcciones encontradas

- El proveedor esperaba `registry.get(InstanceInstallService)` antes de registrarse. Un perfil nuevo que abría Mundos podía esperar indefinidamente sin haber visitado otra pantalla. La dependencia ahora se crea con `getOrCreate` dentro de `installInstanceFile`; descargar un archivo no depende de abrir otra pantalla.
- Dos pruebas iniciales de publicación detectaron un orden distinto de campos del objeto revisado cuando el nombre era implícito. Se canoniza también esa operación; no se relajaron los snapshots.
- La primera fixture Native interceptaba Undici, pero los metadatos usan la implementación `ElectronLauncherApp.fetch` mediante `net.fetch`. Respondía el servicio real con una lista vacía para el ID ficticio. Se sustituyó la intercepción por una redirección de las rutas de metadatos al servidor HTTP local mediante la API oficial [WebRequest.onBeforeRequest](https://www.electronjs.org/docs/latest/api/web-request#webrequestonbeforerequestfilter-listener). Los bytes, hashes, archivos, tareas y guardas siguen usando el pipeline nativo. Se retira el listener al terminar. El diagnóstico temporal de IDs se eliminó del código antes del cierre; sus paquetes/logs no son evidencia final.
- El workflow de migración no recibía `CURSEFORGE_PROXY_URL`, aunque el de release sí. `4ce32ab` proporciona esa misma variable pública del repositorio al build. Se comprobó que existe y contiene únicamente un origen HTTPS válido, sin guardar/imprimir su valor. No se añade ninguna API key al cliente. CI `41352235867` de `2d356e9` comenzó antes de esta corrección; no prueba la configuración nueva.
- CI `41347979179` sobre `8306911` falló en la detección de inventario de shaders modificado; React quedó cancelado por la matriz. Las huellas usaban identidades/timestamps Number. Se usan BigInt e identidades/nanosegundos serializados como strings. Una regresión determinista cambia solamente un nanosegundo y exige rechazar la escritura conservando el shader y sus opciones. No se aumentaron timeouts ni redujeron aserciones.
